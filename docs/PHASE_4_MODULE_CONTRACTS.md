# Phase 4 module contracts

Phase 4 adds transparent intelligence and reporting over the existing synthetic SQLite sample. Nova can use the Google Gemini Developer API when a server-side key is configured, with a deterministic local rule/template fallback otherwise.

## Nova Assistant

- API: `POST /api/ai/assist` with `mode=question` or `mode=content`.
- Question mode sends the user's prompt plus aggregate synthetic counts and saved segment/offer names; it does not send customer-level records or subscriber numbers.
- Content mode returns channel-specific template drafts from user-provided objective, audience, channel, offer, and brief. Drafts require human review and existing approval before campaign use.
- Every response reports the provider/model and data scope. No subscriber contact details are returned and no customer is contacted. Without a Gemini key, the local fallback remains available.
- Gemini API free-tier content may be used by Google to improve products and quotas can change. Keep real subscriber or confidential data out of prompts; configure the key only on the backend.

## Intelligence and analytics

- `GET /api/intelligence/overview`, `/cohorts`, `/campaign-comparison`, `/offer-fit`, and `/signals` return descriptive aggregates, consent-filtered rule-based offer cues, and explicit data review hints.
- Offer-fit outputs contain reasons but no probability or confidence score. There is no evaluated predictive model because the repository has no sufficient longitudinal outcome labels for honest validation.
- Review signals use explicit checks. They are not statistical anomaly detection, significance tests, or causal lift estimates.
- Simulated execution outcomes remain separate from actual provider delivery events.

## Reports and exports

- `GET /api/reports/definitions` lists reports and their data bases; `GET /api/reports/{report_id}/data` returns the current rows.
- CSV and JSON downloads are generated by the browser from those API results.
- `GET/POST /api/reports/schedules` and `PATCH /api/reports/schedules/{schedule_id}` store schedule preferences only. No background scheduler or email delivery is configured.

## Experiment planning

- API: `GET/POST /api/experiments`, `GET/PUT/DELETE /api/experiments/{id}`, and `POST /api/experiments/{id}/preview`.
- Plans require a written hypothesis, primary metric, two to four unique variants, and allocation totaling 100%.
- Preview provides stable aggregate allocation counts for active, consented sample customers. It stores no assignments and has no measured outcomes, lift, or significance calculation.

## Administration and automation overview

- `GET /api/admin/roles` exposes the enforced role/department catalog; `GET/POST /api/admin/users` and `PATCH /api/admin/users/{id}` administer accounts and approvals.
- `GET/PUT /api/admin/settings` stores workspace preferences and reports SQLite, Gemini-key, channel-provider, and session-authentication status.
- These endpoints require administrator access. Workflow Automation summarizes existing journeys, rules, and execution simulations; it is not a separate workflow runtime.
- Audit Logs show searchable local events. They do not provide tamper-proof storage or a production retention policy.

## Enterprise boundary

The UI and API use authenticated HTTP-only cookie sessions, password hashes, and role/department checks over SQLite. Production SSO/MFA, verified corporate email, tenant isolation, a production database, distributed rate limiting, secure provider credentials, background workers, and commercial deployment controls still require infrastructure and identity-provider configuration.
